# ATM9: обновляемый русский перевод

Это инструменты подготовки исходников, а не игровой мод или служба лаунчера. Они не меняют JAR, настройки игры, язык Minecraft, ID квестов, задания, награды, зависимости или прогресс. Русские значения по-прежнему загружает штатный механизм `kubejs/assets/kubejs/lang/ru_ru.json`, только когда игрок выбрал русский язык. Другие языки получают исходные английские значения.

Полный исполняемый маршрут владельца: [OWNER_WORKFLOW.md](OWNER_WORKFLOW.md). Команды `update_atm9_quests.py` фиксируют настоящую опубликованную сборку, воспроизводят pristine author staging, явно обновляют провайдера, выпускают review/lock-data и проверяют обе реальные native restore-оболочки.

Нынешний runtime overlay и фиксированные инструменты `8be48…` / manifest `9ebb5…` сохранены. Для будущей авторской версии есть отдельный opt-in schema2 reader, проверяющий новый upstream lock и точные locale/display rows; версия и число файлов задаются данными. Владелец отдельно принимает новые source/lock-данные и публикует их. Автоматического наложения на рабочую сборку нет.

## Приоритет и происхождение

1. Непустой настоящий перевод из свежего авторского `ru_ru.json`, входящего в точный upstream lock.
2. Совместимый перевод из отдельно скачанного источника Scriptora / CurseHell / CurseMen.
3. Наш ручной запасной перевод, только если fingerprint текущего английского значения совпадает с проверенным.
4. Штатный английский fallback и строка в очереди проверки.

Новая русская строка внешнего источника заменяет нашу прежнюю правку. Исключение ограничено известным ошибочным значением: существующая ручная коррекция содержит fingerprint именно того значения и идентификатор провайдера. Она не переопределяет другое значение, даже если ключ тот же. Настоящий русский текст из свежей авторской сборки всегда выше ручных коррекций.

`englishFingerprint` — SHA256 от `json.dumps(value, ensure_ascii=False, sort_keys=True, separators=(',', ':')).encode('utf-8')`. Для ATM9 значение — строка, не список ATM10. Переносы и форматные символы участвуют в fingerprint. Переформатирование JSON без изменения значения его не меняет.

Кэш сообщества хранит только исходные внешние значения, их fingerprints, момент/источник привязки к английскому тексту и сведения о загрузке/лицензии. Сгенерированный русский JSON и `ownership.json` никогда не используются как авторский источник. Собственные значения не переименовываются в официальные при повторной подготовке.

Релиз Scriptora содержит только RU. Повторная загрузка того же RU не доказывает соответствие изменившемуся английскому тексту. Существующая привязка сохраняется лишь для неизменного EN и того же провайдера. Новому/изменившемуся EN нужна совпадающая EN-таблица провайдера или явная проверка `key -> englishFingerprint`; иначе старая RU пропускается и работает английский fallback. Недоступность провайдера оставляет прежний проверенный source-only кэш, но не обновляет привязки.

В принятом переводе есть один ключ без исходного EN: `atm9.quest.ma.desc.atm`. Для него не придуман EN fingerprint. Существующий проверенный перевод привязан к точным SHA исходных SNBT-файлов, содержащих ссылку на этот ключ. Изменение контекста или появление настоящего EN отменяет эту запасную ветку и отражается в отчёте.

## Подготовка новой версии

Сначала штатный загрузчик исходной авторской сборки должен создать отдельное чистое дерево по **новому** точному upstream lock. Не передавать установленную игру, дерево после нашей локализации или персональный мир. Подготовка проверяет все строки lock, SHA/размеры, точный состав JAR и лишние файлы в авторских каталогах до любой обработки перевода. Изменения/отсутствие JAR и неизвестные BASE-файлы остаются ошибкой. Эта проверка не заменяет проверку совместимости модов, native permission gates или игровой запуск новой сборки.

При восстановлении уже опубликованного дерева оболочка сначала выполняет `normalize` **его закреплённым профилем**, затем восстанавливает точный исходный BASE и применяет тот же профиль заново. Schema1 использует неизменённый importer, schema2 — strict locked restore без его прежнего hardcoded client archive. Подготовка другой авторской версии сначала требует отдельного нового upstream lock. Старый профиль не применяется к неизвестным новым входам. Потерянные tracked author overrides нельзя восстановить из одних display-spans: нужен checkout или новый полный author import.

Сам `normalize` восстанавливает только BASE-spans и не удаляет support-файлы. Поэтому повторная подготовка использует отдельный pristine author staging: он заполняется только точными строками нового upstream lock после штатного импорта. Наличие/отсутствие native RU определяется этим lock, а не прежним сгенерированным RU или notices. При переносе из опубликованного дерева оболочка отдельно проверяет точные известные support-файлы и не включает их в авторский staging; неизвестные файлы нельзя молча отбрасывать. Прежний managed RU не становится авторским входом. `stage-author` восстанавливает pristine staging только из закреплённых BASE-строк и сообщает исключённые additions/support.

Пример команд из корня исходной сборки с установленным Python 3.12:

```powershell
python tools/atm9_ru_future.py refresh-community `
  --english <pristine-author>/kubejs/assets/kubejs/lang/en_us.json `
  --previous tools/atm9_ru_future/community-source.json `
  --out <research>/new-community-source.json `
  --report <research>/community-report.json

python tools/atm9_ru_future.py prepare `
  --source <pristine-author> --source-lock <new-upstream-lock.json> `
  --community <research>/new-community-source.json `
  --out <fresh-overlay> --report <research>/prepare-report.json
```

`prepare` никогда не пишет во входное дерево. Выход должен быть отдельным и пустым. Он содержит только разрешённые локализованные ресурсы и source-only profile/ownership/report. Результат не накладывается автоматически на active source.

`--require-fresh` делает недоступность внешнего провайдера явной ошибкой только по запросу. `--require-complete` включает отдельный строгий gate покрытия для конкретной текущей публикации. По умолчанию старые/новые непереведённые ключи не блокируют обновление сборки; они попадают в `refreshQueue` и остаются на английском. Неизвестная будущая схема/путь locale выдаёт `SKIPPED_UNSUPPORTED_TRANSLATION_SOURCE`, не создаёт overlay и оставляет все авторские ресурсы нетронутыми. Это не подавляет несовпадение BASE/JAR.

## Inline-текст SNBT и обратимое восстановление

Сохранённые старые текстовые spans повторно применяются только к целому файлу, SHA которого точно совпал с ранее проверенным исходником. Изменившийся/удалённый файл не получает старых offsets. Добавленные/изменённые главы перечисляются в `nativeQuestDisplayReview`; непроверенный inline-текст остаётся исходным. Уже существующие native lang-макросы новых глав переводятся обычным слиянием EN/RU, если для их ключей есть совместимый источник.

Известные inline-алиасы сохраняют исходный английский текст в EN и русский в RU. EN меняется только insertion-spans; прежние ключи/значения и байты не заменяются. Коллизия с иным авторским значением отменяет локализацию соответствующего SNBT-файла. Exact-English reuse-алиасы следуют обновившемуся однозначному авторскому/внешнему переводу базового ключа; неоднозначный случай сохраняет проверенный запасной текст.

`atm9_ru_display.py` поддерживает два профиля:

- schema 1: прежняя строго закреплённая 1.1.1/107-файловая схема;
- schema 2: новая объявленная `sourceVersion` и явные точные строки `files[]`, без фиксированного количества/версии. Разрешены только `config/ftbquests/quests/*.snbt`, insertion-only EN и, если свежий автор действительно поставляет его как BASE, обратимая целиком RU-таблица. Никакие JAR или произвольные скрипты не разрешены.

Строка profile: `path`, `originalSha256`, `originalSizeBytes`, `localizedSha256`, `localizedSizeBytes`, `edits[]`. Каждый edit содержит byte-offset с обеих сторон и Base64 точных старых/новых байт. У SNBT дополнительно `displayPath`; допустимые display-leaves: `title`, `subtitle`, `description`, `hover`. Новый профиль содержит ссылку на прежнюю native structural proof и список точных повторно использованных исходников. Это **не утверждение** о новом полном native AST-анализе неизвестных будущих глав.

```powershell
python tools/atm9_ru_display.py normalize --root <tree> --manifest <pinned-profile.json>
# unchanged author importer + exact original BASE verification
python tools/atm9_ru_display.py apply --root <tree> --manifest <pinned-profile.json>
python tools/atm9_ru_display.py verify --root <tree> --manifest <pinned-profile.json>
```

Каждый режим сначала проверяет/восстанавливает все существующие входы в памяти. Неизвестный hash, link, недопустимый путь или span прерывает операцию до записи. apply/normalize повторяемы; normalize допускает отсутствующий файл только для последующего восстановления авторским importer. Полная транзакция на случай аварии ОС не заявляется.

## Интеграция Original и Modified

Оба владельца должны использовать один и тот же подготовленный locale overlay/профиль исходной ATM9. Оригинальная проверка состава BASE и exact-hash политика Modified остаются строгими. Публикационный lock закрепляет digest инструментов, данных, профиля и всех разрешённых original/localized строк; проверяет их привязку к точному текущему upstream lock; не принимает новые пути от непроверенного профиля автоматически.

Будущий авторский native RU потребует отдельной узкой BASE-строки для этого locale; сегодня RU остаётся обычным support-файлом. Статические notices Scriptora/MIT и существующие notices локализации следует сохранить. Ни launcher C#, ни Java-agent, ни новый игровой JAR для этого маршрута не нужны.

Автоматическое обновление никогда не скачивает/накладывает старые главы Scriptora: из ZIP читается только точный RU JSON, без извлечения других файлов. Проверяются release identity, отсутствие draft/prerelease, размер/доступный GitHub digest, единственность ресурса и MIT-лицензия точного авторского repository commit с байтово совпадающим RU. Если новый источник не удовлетворяет этому контракту, прежний проверенный кэш остаётся доступен, а обновление авторской сборки не блокируется только из-за перевода.

Новые внешние переводы всё равно требуют обычной проверки native formatter/макросов и игрового приёмочного маршрута перед публикацией. Эти тесты не доказывают семантическую правильность ещё не существующих внешних строк. Новый inline-текст можно добавить отдельной проверкой display-spans и native AST, не замораживая авторские обновления ожиданием полного перевода.

## Проверки кандидата

```powershell
python -m unittest discover -s tools -p test_atm9_ru_future.py -v
python -m unittest discover -s tools -p test_update_atm9_quests.py -v
```

Портативный набор проверяет приоритет новых авторских значений, известную ошибочную RU, stale EN, RU-only refresh, источник/ownership, смену провайдера, native RU, изменённые/новые главы, коллизии, неизвестные JAR, точные reversible spans, глобальный preflight, idempotence, новую версию без count gate, безопасный отказ от новой locale-схемы и приоритет новой внешней строки без EN в неизменном точном native-контексте. Owner workflow дополнительно проверяет known-support exclusions, долгие Windows пути, pinned retry и отказ от unknowns до записи. Проверка реальной текущей 1.1.1 выполняется явным owner-маршрутом, а не вечным условием старого числа глав в unit/CI: 1 794 BASE-строки, все 108 payload-ресурсов и normalize/restore/apply/verify настоящих Original/Modified wrappers. Текущий RU остаётся 7 538 ключей/SHA256 `18fde6566400e636cc82fa3fa111cd76359c9266d828180f318ce892262772e4`.
